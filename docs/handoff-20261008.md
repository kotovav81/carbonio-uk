## 12-key follow-up

The proposal is not an installation or translation merge. It is a clarification
package for Zextras. It uses code fallbacks, established Ukrainian terminology,
and non-empty peer locales as context. Before applying any item:

1. Ask upstream whether the English key should have a canonical value.
2. Confirm the UI context and placeholder names.
3. Apply only approved values to the relevant upstream i18n repository.
4. Re-run audit and validation against the new upstream commit.

Do not add a `{{count}}` placeholder to `calendar.label.attendee_one`; the
English key has no placeholder. The contacts import key uses `{{number}}`.

## Upstream submission order

Start with separate PRs for:

1. Mail i18n;
2. Calendar i18n;
3. Contacts i18n;
4. Files i18n;
5. Shell i18n plus the separate Shell functional patch.

Then submit Login, Auth, Tasks, Search, Collaboration, Storages, and Admin
Login. Do not combine catalogs from different repositories.

The Shell functional patch and Shell i18n label patch are separate by design.
Apply with `git apply --check` before making branches.
